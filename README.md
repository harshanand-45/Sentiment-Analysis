# Sentiment Analysis for User Feedback

A complete, beginner-friendly Sentiment Analysis tool that classifies any text
(reviews, comments, feedback) as **Positive**, **Neutral**, or **Negative**,
using classic NLP (NLTK preprocessing) + TF-IDF + Logistic Regression, with a
Streamlit web app for live predictions and batch CSV predictions.

---

## 1. Project Overview

This project was built as the "Sentiment Analysis Intern Project" — a natural
next step after building a chatbot, moving from conversational NLP to text
**classification**. It classifies free-form text feedback into one of three
sentiment classes.

## 2. Objective

Build a tool that automatically classifies text feedback as **Positive**,
**Neutral**, or **Negative**, with a working local web app for real-time and
batch predictions.

## 3. Dataset

### ⚠️ Important note on the dataset used here
This project ships with a **synthetic, template-generated dataset**
(`data/dataset.csv`, 2,100 samples, ~700 per class), created by
`data/generate_dataset.py`. It exists so that you can run the **entire**
pipeline (train → evaluate → app) immediately, with no downloads, API keys,
or Kaggle account required.

Because the synthetic sentences follow clear templates, the model reaches
**~100% test accuracy** on it — this is expected and mainly demonstrates that
the *pipeline* works correctly end-to-end, not that the model is production-grade.
**For a real portfolio project, swap in a real-world dataset** (instructions below).

### Using a real dataset instead (recommended)
1. Get a real sentiment dataset, for example:
   - [Kaggle: Sentiment140 (Twitter)](https://www.kaggle.com/datasets/kazanova/sentiment140)
   - [Kaggle: Amazon Product Reviews](https://www.kaggle.com/datasets) (search "amazon reviews")
   - Any Yelp/product review dataset with star ratings
2. Convert it to a CSV with **exactly two columns**:

   | text | label |
   |------|-------|
   | "The product was great!" | Positive |
   | "It was okay, nothing special." | Neutral |
   | "Terrible service, never again." | Negative |

   - `label` must be exactly one of: `Positive`, `Neutral`, `Negative`
   - If your source uses star ratings (1–5), map them like this:
     - 1–2 stars → Negative
     - 3 stars → Neutral
     - 4–5 stars → Positive
3. Save the file as `data/dataset.csv` (overwrite the generated one).
4. Re-run `python train.py`.

## 4. Preprocessing (NLTK)

Implemented in `src/preprocessing.py`, and used identically during training
**and** prediction (so the model always sees text prepared the same way):

1. Lowercase the text
2. Remove URLs
3. Remove HTML tags
4. Remove special characters / punctuation / numbers
5. Tokenize (split into words)
6. Remove stopwords (e.g. "the", "is", "at")
7. Lemmatize (e.g. "running" → "run")

## 5. TF-IDF

We use `sklearn.feature_extraction.text.TfidfVectorizer` with:

| Parameter | Value | Why |
|---|---|---|
| `max_features` | 5000 | Caps vocabulary size for speed/memory while keeping the most informative words |
| `ngram_range` | (1, 2) | Includes single words AND two-word phrases (helps capture things like "not good") |
| `min_df` | 2 | Ignores words that appear in fewer than 2 documents (typos/noise) |
| `max_df` | 0.9 | Ignores words appearing in over 90% of documents (too common to be useful) |

The fitted vectorizer is saved to `models/tfidf_vectorizer.pkl` and reused for
every prediction, so training and inference use the exact same vocabulary.

## 6. Model

**Logistic Regression** trained on TF-IDF features (`class_weight="balanced"`,
`random_state=42` for reproducibility). This is the simple, fast approach
recommended as the primary approach in the project spec. BERT/DistilBERT was
intentionally **not** used, since the spec marks it as an optional advanced
approach and asks for the simple working implementation first.

## 7. Training

Run `python train.py`. It will:
1. Load `data/dataset.csv`
2. Validate it (correct columns, valid labels, no empty rows)
3. Clean/preprocess all text
4. Split into train (80%) / test (20%), stratified by class
5. Fit TF-IDF on the training set
6. Train the Logistic Regression model
7. Evaluate on the test set
8. Save the model, vectorizer, and an evaluation report

## 8. Evaluation

`train.py` prints and saves:
- **Accuracy**
- **Precision** (weighted average across classes)
- **Recall** (weighted average across classes)
- **F1-score** (weighted average across classes)
- Full per-class **classification report**
- **Confusion matrix** (as text, JSON, and a PNG image)

Results are saved to:
- `models/evaluation_report.json` — full metrics + confusion matrix as numbers
- `models/confusion_matrix.png` — visual confusion matrix image

## 9. Results (on the included synthetic dataset)

Using the default `data/dataset.csv` generated by `generate_dataset.py`:

- Accuracy: ~1.00
- Precision / Recall / F1 (weighted): ~1.00

**Note:** these near-perfect scores reflect the synthetic dataset's simple
templates, not real-world performance. With a real dataset (see Section 3),
expect more realistic scores (commonly ~70–85% accuracy for Logistic
Regression + TF-IDF on 3-class sentiment).

## 11. How to Install Dependencies (Windows)

Open **Command Prompt (cmd)** or **PowerShell** in the project folder and run:

```bat
:: 1. Create a virtual environment
python -m venv venv

:: 2. Activate it
venv\Scripts\activate

:: 3. Upgrade pip (optional but recommended)
python -m pip install --upgrade pip

:: 4. Install all required packages
pip install -r requirements.txt
```

You'll know the virtual environment is active because your prompt will show
`(venv)` at the start of the line.

### Download required NLTK resources
With the virtual environment still active, run:

```bat
python -c "import nltk; nltk.download('punkt'); nltk.download('punkt_tab'); nltk.download('stopwords'); nltk.download('wordnet'); nltk.download('omw-1.4')"
```

(`src/preprocessing.py` will also try to auto-download these the first time
it runs, but doing it manually first avoids any first-run delay/errors.)

## 12. How to Train the Model

Still inside the activated virtual environment:

```bat
:: (Optional) regenerate the sample dataset
python data\generate_dataset.py

:: Train the model
python train.py
```

You should see step-by-step progress printed (loading, validating, cleaning,
splitting, vectorizing, training, evaluating, saving) and, at the end, files
appear inside the `models/` folder.

## 13. How to Run the Streamlit App

```bat
streamlit run app.py
```

This opens a browser tab (usually at `http://localhost:8501`). If it doesn't
open automatically, copy that URL into your browser manually.

## 14. How to Test It With Sample Sentences

In the **Single Text Prediction** tab, try pasting these examples:

| Text | Expected sentiment |
|---|---|
| "This app exceeded my expectations, I loved every part of it!" | Positive |
| "The product was okay, nothing special but not bad either." | Neutral |
| "This was a complete disappointment and a waste of money." | Negative |

Click **Predict Sentiment** and check the coloured result box plus the
probability bar chart below it.

## 15. How to Test Batch CSV Prediction

1. Create a CSV file (e.g. `sample_batch.csv`) with a column named exactly
   `text`, for example:

   ```csv
   text
   "I love this product, it's amazing!"
   "It was fine, nothing to complain about."
   "Terrible experience, would not recommend."
   ```

2. Go to the **Batch CSV Prediction** tab in the app.
3. Upload the CSV.
4. The app adds `predicted_sentiment` and `confidence_percent` columns and
   shows a sentiment distribution chart.
5. Click **Download Results as CSV** to save the labeled file.

## 16. Expected Output

- Single prediction: a coloured box (green/grey/red) showing the predicted
  label, plus a bar chart of probabilities for all 3 classes and their
  exact percentages.
- Batch prediction: the uploaded table with two new columns
  (`predicted_sentiment`, `confidence_percent`), a distribution chart, and a
  downloadable CSV.

The structure follows the suggested layout from the project spec exactly,

## 18. Troubleshooting

**"Model files not found" error in the Streamlit app**
→ Run `python train.py` first. This creates `models/sentiment_model.pkl` and
`models/tfidf_vectorizer.pkl`, which the app needs to load.

**`ModuleNotFoundError` for pandas/sklearn/nltk/streamlit**
→ Make sure your virtual environment is activated (`venv\Scripts\activate`)
and that you ran `pip install -r requirements.txt` inside it.

**NLTK resource errors (e.g. "Resource punkt not found")**
→ Run the NLTK download command from Section 11 again. Some corporate/school
networks block NLTK's download server — if so, try a different network or a
personal hotspot.

**Dataset not found error when running `train.py`**
→ Run `python data\generate_dataset.py` to create `data/dataset.csv`, or
place your own dataset there with `text` and `label` columns.

**"Missing required column 'text'" when uploading a CSV in batch mode**
→ Your CSV's text column must be named exactly `text` (lowercase). Rename
the column in Excel/your spreadsheet tool and re-upload.

**Empty/blank prediction result**
→ This happens if, after cleaning, no words remain (e.g. the input was only
a URL or symbols). Try a longer, more descriptive sentence.

**Streamlit opens but the page is blank / stuck loading**
→ Stop the app (Ctrl+C in the terminal) and re-run `streamlit run app.py`.
Also check that no other process is using port 8501.

**Retraining after changing `src/preprocessing.py`**
→ Always re-run `python train.py` after changing preprocessing logic, since
the saved TF-IDF vectorizer and model expect text cleaned the exact same way.
